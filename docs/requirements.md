## システムアーキテクチャ

| AsIs/ToBe比較 | アーキテクチャ構成・課題と解決策 |
| :--- | :--- |
| **AsIs（現状）** | 現状は、各製造プロセス（加工、組立、検査）のデータと基幹データ（ERP）が各システムにサイロ化して保存されています。<br>そのため、品質異常発生時などの横断的な分析を行う際、担当者が各システムから手動でデータを抽出し、Excel等でクレンジング・名寄せ（シリアル番号での突合など）を行っています。この手作業によるデータ準備に多大な工数（数日単位）がかかっており、迅速な真因究明や予知保全のボトルネックとなっています。また、属人的なデータ抽出により、ガバナンス上のリスクも存在します。 |
| **ToBe（理想像）** | 各ソースシステムのデータを、国内クラウドリージョン上に構築する統合分析基盤「弊社分析基盤D」へ自動集約します。<br><br>**① 3層アーキテクチャによるスケーラビリティと証跡確保**<br>データは「Raw（生データ蓄積）」「一時（前処理・匿名化）」「参照（多次元分析モデル）」の3層で管理します。これにより、生データのトレーサビリティを確保しつつ、エンドユーザーには使いやすい形（スタースキーマ等）でデータを提供します。<br><br>**② バッチとストリーミングのハイブリッド処理**<br>ERPやQMS等の日次/週次バッチ処理と、IoTセンサーデータの準リアルタイム処理（マイクロバッチ/ストリーミング）を適材適所で組み合わせ、要件に応じたデータ鮮度（SLA）を担保します。<br><br>**③ 堅牢なセキュリティとガバナンス**<br>Raw層へのアクセスは管理者のみに厳しく制限し、一時層で個人情報（作業者マスタ等）のハッシュ化・匿名化を行います。参照層では適切なアクセス制御（RBAC）とデータマスキングを実施することで、データ活用の利便性と高いセキュリティレベルを両立させます。 |
